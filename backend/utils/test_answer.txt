传统大模型推理和外部行动通常分开研究。模型要么只生成思考过程，要么只生成行动计划，难以根据环境反馈动态调整。ReAct 将推理轨迹和行动交替结合，使模型能够边思考、边获取信息、边修正计划。
ReAct 是 Reasoning and Acting 的缩写，表示“推理与行动”。
模型按照“Thought → Action → Observation”的循环运行：先分析当前问题，再调用外部工具，读取工具返回的观察结果，最后继续推理或执行下一步行动。
Chain-of-Thought 主要关注内部推理过程，通常不主动调用外部环境；ReAct 在推理过程中加入行动，可以通过搜索或工具获得实时信息。
纯工具调用通常强调“识别工具并执行”，但缺少连续的任务分解和错误修正。ReAct 会根据工具结果更新后续计划。
模型只能依赖参数记忆进行推理，缺少外部事实验证，因此可能出现事实错误，并且错误会沿着后续推理不断传播。
一次性生成完整计划后，如果中途环境发生变化或某一步失败，模型通常难以及时调整；同时，行动原因也不容易解释。
Observation 是外部环境或工具返回的结果，例如搜索结果、网页内容、数据库查询结果或任务执行状态。
模型会把 Observation 作为下一轮上下文，根据新信息判断当前计划是否正确，并决定继续调用工具、修改计划或输出最终答案。
因为模型不会完全依赖最初的推理结果，而是可以通过外部行动获得新的事实，并根据反馈修正后续步骤。
论文同时验证了知识问答、事实验证和交互式决策任务。
主要包括 HotpotQA 问答任务和 FEVER 事实验证任务。
HotpotQA 通常需要组合多个事实进行多跳推理，适合验证模型能否通过多次检索和推理完成复杂问题。
FEVER 用于判断陈述是否真实，适合验证模型通过外部资料查证事实的能力。
论文在 ALFWorld 和 WebShop 两个交互式环境中进行了实验。
根据论文摘要，ReAct 相比模仿学习和强化学习方法，绝对成功率提升了 34%。
根据论文摘要，ReAct 相比对比方法，绝对成功率提升了 10%。
ReAct 保留了任务执行过程中的推理和行动轨迹，面试官或开发者可以看到模型为什么调用某个工具，以及工具结果如何影响下一步决策。
当前项目中的笔记搜索、知识库检索、创建笔记、长期记忆和工作记忆都可以看作 Agent 工具。可以借鉴 ReAct，让模型根据用户意图动态选择工具，并结合工具返回结果继续完成任务。
ReAct 仍然依赖模型自身的工具选择能力，可能出现错误调用、循环调用或计划不完整等问题。生产系统还需要增加最大迭代次数、超时、重试、工具权限、日志追踪和失败兜底机制。
